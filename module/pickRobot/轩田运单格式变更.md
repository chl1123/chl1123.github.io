## 下单接口变更说明
下单的IP、Port及Path都不变，只变更运单数据格式。
#### 原运单数据格式：
```json 
{
    "id":"2f4ba4cc-3bad-11ed-9a46-0242ac110004",    //运单号，需保证唯一性 
    "fromLoc":"GD-ZB-02",            //起点库位
    "toLoc":"A5-2-2",                         //终点库位
    "vehicle":"",
    "group":"",
    "goodsId":"03-04-000312",        //货物编号
    "loadPostAction":{
        "configId":""
    },
    "unloadPostAction":{
        "configId":""
    }
}
```
**字段说明："id"为运单号，需保证唯一性，"fromLoc"为起点库位，"toLoc"为终点库位，"goodsId"为货物编号，其余字段均未实际使用。
详细文档参考：https://books.seer-group.com/public/rdscore/master/zh/api/http/order/joinOrder.html **

#### 变更后运单数据格式：
```json
{
    "id":"task1",    // 运单号，建议使用 UUID
    "area": "inside/outside",        // 运单执行区域：库内/库外
    "blocks":[         // 运单任务块，多个任务块按顺序依次执行
      //取货任务块，"load" 任务需附加 "scriptArgs" 参数字段
        {                             
            "blockId":"b1",                   // 任务块编号，建议使用UUID
            "location":"GD-ZB-02",       // 任务块库位
            "binTask":"load",             // 库位中设置的任务类型，如 load 表示取货，unload 表示放货
            "goodsId":"001",                 // 货物编号
            "scriptArgs":{                        // 脚本参数
                "locType":"roller/shelf",                // 库位类型，辊筒线/货架
                "recycleBin":"GD-ZB-01",             // 货物回收库位，用于取错料箱时回收该料箱
                "goodsIdGroup":["001", "002", "003"]             // 当前运单如task1所需要的货物列表
            }
        },
      // 放货任务块，"unload" 任务
        {
            "blockId":"b2",         // 任务块编号，建议使用UUID
            "location":"GD-ZB-01",          // 任务块库位
            "binTask":"unload",             // 库位中设置的任务类型
            "goodsId":"001"                   // 货物编号
        }
    ],
    "complete":false                        // 是否封口，封口后该运单不可再添加任务块
}
```

## 回调接口变更
回调接口的 IP、Port及Path不变，只变更回调数据格式。
#### 原回调数据格式：
```json
[
    {
        "$id":1,
        "$type":"Nkd.Custom.BusinessObjects.AGVTaskInfo,Nkd.Custom.BusinessObjects",
        "taskId":"001",
        "vehicle":"AMB-01",
        "message":"success",
        "status":"FINISHED"
    },
    {
        "$id":1,
        "$type":"Nkd.Custom.BusinessObjects.AGVTaskInfo,Nkd.Custom.BusinessObjects",
        "taskId":"001",
        "vehicle":"AMB-01",
        "message":"success",
        "status":"FINISHED"
    }
]
```
原回调流程中，一个运单对应一次回调，taskId 字段对应运单号id，回调数据中分为两段数据，分别表示取货完成情况和放货完成情况

#### 变更后回调数据格式：
```json
[
    {
        "$id":1,
        "$type":"Nkd.Custom.BusinessObjects.AGVTaskInfo,Nkd.Custom.BusinessObjects",
        "taskId":"task1",
        "blockId": "b1",
        "vehicle":"AMB-01",
        "message":"success",
        "status":"FINISHED",
        "goodsId": "00001"
    },
    {
        "$id":1,
        "$type":"Nkd.Custom.BusinessObjects.AGVTaskInfo,Nkd.Custom.BusinessObjects",
        "taskId":"task1",
        "blockId": "b2",
        "vehicle":"AMB-01",
        "message":"success",
        "status":"FINISHED",
        "goodsId": "00002"
    }
]
```
变更后，一个运单对应一次回调，taskId 字段对应运单号id， 增加 blockId 字段表示运单中的任务块编号，增加 goodsId 字段表示该任务块实际操作的货物，
回调数据中将列出所有任务块的完成情况。


脚本上报的异常信息需要附加到运单状态 orderDetails 接口的响应数据中，该信息最终需要回传到客户 WMS
